# ADR-001: Выбор языка серверной части

**Статус:** Принято
**Дата:** 2026-03-29

## Контекст

Необходимо выбрать язык программирования для серверной реализации протокола FProto. Основные кандидаты -- Go и Rust. Ключевые критерии: наличие библиотек для Noise Protocol, Kafka, QUIC, WebSocket; производительность сетевого ввода-вывода; скорость разработки и порог входа.

## Решение

Выбран **Go** в качестве языка серверной части.

## Обоснование

| Критерий | Go | Rust |
|----------|----|----|
| Noise Protocol | `flynn/noise` -- зрелая, активно поддерживается | `snow` -- хорошая, но меньше примеров |
| Kafka | `segmentio/kafka-go` -- нативный Go-клиент | `rdkafka` -- обёртка над C-библиотекой |
| QUIC | `quic-go` -- полноценная реализация RFC 9000 | `quinn` -- хорошая, на базе tokio |
| WebSocket | `gorilla/websocket` -- de-facto стандарт | `tungstenite` + `tokio-tungstenite` |
| gRPC | `grpc-go` -- официальная реализация | `tonic` -- хорошая, на базе tokio |
| Protobuf | `google.golang.org/protobuf` -- стандартная | `prost` -- хорошая |
| Concurrency | Горутины, простая модель | async/await, сложнее, но безопаснее |
| Скорость разработки | Высокая | Средняя (борьба с borrow checker) |
| Производительность | Высокая (достаточна для 500K+ msg/sec) | Максимальная |

Go выбран за баланс производительности и скорости разработки. Экосистема Go содержит зрелые библиотеки для всех требуемых компонентов. Для прототипирования (Фаза 0) скорость разработки критичнее максимальной производительности.

## Последствия

- Серверный код пишется на Go 1.22+
- Используются стандартные Go-инструменты: `go test`, `go build`, `golangci-lint`
- CI настроен на сборку Go-проекта
- Криптографически чувствительные компоненты могут быть переписаны на Rust в будущем (CGo / отдельный микросервис)
