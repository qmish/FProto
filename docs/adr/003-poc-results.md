# ADR-003: Результаты PoC (Фаза 0)

**Статус:** Принято
**Дата:** 2026-03-29

## Контекст

В рамках Фазы 0 (Исследование и прототипирование) реализован Proof of Concept: Noise XX handshake поверх WebSocket с эхо-сервером. Необходимо оценить результаты и принять решение о продолжении реализации.

## Реализовано

- Protobuf-схемы (Frame, AppMessage, ChatMessage, Command, MediaChunk, Ack, Ping/Pong, SyncRequest, SenderKeyDistribution)
- Noise_XX_25519_ChaChaPoly_BLAKE2s handshake (библиотека `flynn/noise`)
- WebSocket-транспорт (библиотека `gorilla/websocket`)
- Эхо-сервер с полной интеграцией Noise + WebSocket
- 22 теста (11 протокол, 8 криптография, 3 интеграционных)

## Результаты бенчмарков

**Платформа:** Windows, Intel Core i5-11400F @ 2.60GHz, 12 потоков

| Бенчмарк | Операций/сек | Latency | Allocs |
|----------|-------------|---------|--------|
| Noise Handshake (WS) | ~1,195/сек | ~836 мкс | 365 allocs, 194 КБ |
| Encrypt (256B payload) | ~2,590,000/сек | ~386 нс | 2 allocs, 304 Б |
| Echo Round-Trip (WS+Noise) | ~20,370/сек | ~49 мкс | 15 allocs, 1.4 КБ |

### Анализ

- **Handshake latency (~836 мкс):** Укладывается в целевые 50 мс с большим запасом. Handshake выполняется один раз при подключении.
- **Encrypt throughput (~2.6M ops/sec):** Превышает целевые 50K msg/sec на одном ядре в 50+ раз. ChaCha20-Poly1305 крайне эффективен.
- **Echo round-trip (~49 мкс):** Полный цикл шифрование -> WS передача -> расшифровка -> формирование ответа -> шифрование -> WS передача -> расшифровка. ~20K ops/sec на одном соединении.

## Решение

**Продолжить реализацию** протокола FProto на Go с текущим технологическим стеком.

### Обоснование

1. Производительность криптографии превышает требования на порядки
2. Библиотека `flynn/noise` стабильна и корректно реализует паттерн XX
3. `gorilla/websocket` показывает предсказуемую производительность
4. 22 теста покрывают основные сценарии и edge cases
5. Архитектура модульная -- транспорт отделён от криптографии через интерфейсы

### Риски

- `flynn/noise` v1.1.0 зависит от `golang.org/x/crypto` старой версии -- может потребовать обновление или форк
- Для production потребуется профилирование при высоком числе concurrent connections
- Бенчмарки проведены на Windows; на Linux (production) результаты будут отличаться

## Последствия

- Переход к Фазе 1: реализация Session Manager, полноценной криптографии, QUIC и gRPC транспортов
